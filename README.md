# wglTest<br><br>
・Ryzen7-5700G＆内蔵グラフィクス、Ryzen5-5600＆RTX3050で開発<br><br>
・Microsoft Visual Studio Professional 2026 (64 ビット)<br><br>
・Version 18.0.0<br>
・ISO C++17 標準 (/std:c++17)<br>
・ツールセット v145<br>
・Windows 10 SDK (10.0.2621.0)<br><br>
経緯<br><br>
・個人的にいわゆるゲームエンジン的なものを作りたい欲求はあった。<br>
・だが、UnityやUnrealEngine等の既存エンジンが強力すぎて、<br>
　わざわざ一から作る意味があまりないように思えていた。<br>
・しかし必要だから作りたいのではなく、作りたいから作るのだ！と割り切って作業開始。車輪の再発明でも楽しい。コピーバンドみたいなもの。<br>
 ターゲットはDirectX9⇒DirectX11・DXUT⇒DirectX12と変遷したがマルチプラットフォーム大事、とOpenGL(Win) or OpenGLES(Android)と定める。<br>
・まずは3Dモデルの読み込みから始めることにした。3DモデルフォーマットはFBXに決定。∵サンプルになるシーン入手がしやすそうだったので。<br>
 adobeの公式FBXSDKを使う→ロード再生できた⇒マルチプラットフォームやfbx以外もサポートしたい<br>
 Assimpを試す→非Win環境用バイナリ入手性・クォータニオン実装のバグ等難点があった<br>
 OpenFBXを試す→マニュアルが無く使いにくかった<br>
 ufbxを試す→マニュアルがある！⇒採用<br>
 追加でMMDも出せたら面白いかな？と試行する→公式なサポートライブラリなど無さそうなので発見できたサンプル等を頼りにやってみる。<br>
 ⇒ソフトウェアデフォームで表示できたが、シェーダデフォームはTODOリストに積む。<br>
・各オブジェクトで依存性の有無を問わない処理のディスパッチをシングルスレッドのいにしえのタスクシステムで実装してみる。<br>
 オブジェクトの挙動制御にLUAやC#等をスクリプト言語として使う案も考えたが、<br>
 広げすぎると収拾がつかなくなりそうなので、まずはC++でクラスを書くことにする。<br>
 ブループリントのようなノードベースのビジュアルスクリプティングも面白そうだが、妄想で留める。<br>
・途中VisualStudioが2026になった→ツールセットv145で一部ライブラリがリンク出来ず困ったりした。<br>
